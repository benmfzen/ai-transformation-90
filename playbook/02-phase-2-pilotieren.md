# Phase 2 — Pilotieren (Tag 31–60)

**Leitfrage:** Funktioniert es messbar — im echten Prozess, mit echten Mitarbeitenden?

**Deliverables:** 3 unterschriebene [Pilot-Charters](../templates/pilot-charter.md) · 3 durchgelaufene Piloten mit Vorher/Nachher-Metriken · Pilot-Review mit Skalierungs-/Stopp-Entscheidung je Pilot

---

## Woche 5 (Tag 31–37): Piloten aufsetzen

- [ ] Pro Pilot ein [Charter](../templates/pilot-charter.md) unterschreiben lassen: Zielmetrik, Baseline, Abbruchkriterium, Champion, Zeitbudget der Beteiligten
- [ ] Baseline **vor** dem Start messen (z.B. Ø-Bearbeitungszeit pro Ticket über 2 Wochen rückwirkend) — ohne Baseline ist jedes Ergebnis anfechtbar
- [ ] Tooling minimal aufsetzen ([Freigabe-Checkliste](../templates/tool-checkliste.md)): bestehende Verträge nutzen (M365 Copilot, ChatGPT Team o.ä.), keine Neueinkäufe > 5 T€
- [ ] Datenschutz-Kurzcheck je Pilot gegen die [AI-Richtlinie](../governance/ai-richtlinie.md): Welche Daten dürfen rein, welche nicht?
- [ ] Pilotteams benennen: je 3–5 Personen, freiwillig, vom Champion ausgewählt

## Woche 6–8 (Tag 38–58): Piloten laufen

- [ ] Wöchentlicher 30-Min-Check-in pro Pilot: Was klemmt, was überrascht, Metrik-Zwischenstand
- [ ] **Demo-Freitag** einführen: 20 Minuten, offen für alle, Champions zeigen echte Arbeitsergebnisse — das ist das wirksamste Change-Instrument des ganzen Programms
- [ ] Hindernisse zentral loggen (Datenzugang, Rechte, Qualität) — diese Liste ist Rohmaterial für das Phase-3-Betriebsmodell
- [ ] Wöchentlicher [Status-Report](../templates/status-report.md) an GF, eine Seite, keine Folien
- [ ] Ab Tag 50: Messdaten konsolidieren, Interviews mit Pilotteams (Akzeptanz, Aufwand, Grenzen)

## Die 3 Piloten im Case (NORDWERK)

| # | Abteilung | Use Case | Zielmetrik | Ergebnis (Case) |
|---|---|---|---|---|
| P1 | Kundenservice | Antwortentwürfe + automatische Ticket-Kategorisierung | Ø-Bearbeitungszeit −30 % | **−38 %**, Erstlösungsquote +9 pp → skalieren |
| P2 | Vertrieb | Angebotserstellung aus Anfrage + Produktdaten | Durchlaufzeit Angebot −50 % | **−55 %** (4,2 → 1,9 Tage) → skalieren |
| P3 | Finanzen & Controlling | Eingangsrechnungs-Extraktion + Kommentierungs-Entwürfe Monatsbericht | Manuelle Erfassung −60 % | **−45 %**, Qualität ok, Integration aufwendig → skalieren mit angepasstem Scope |

## Woche 9 (Tag 59–60): Pilot-Review

- [ ] Ergebnisse gegen Charter prüfen ([Entscheidungsvorlage Tag 60](../templates/entscheidungsvorlage.md)): Zielmetrik erreicht? Abbruchkriterium gerissen?
- [ ] Je Pilot eine von drei Entscheidungen: **skalieren / anpassen & verlängern / stoppen**
- [ ] Champions präsentieren selbst vor der GF — nicht die Programmleitung. (Der Unterschied in der Glaubwürdigkeit ist enorm.)
- [ ] Lessons Learned dokumentieren: Was braucht Skalierung an Daten, Rechten, Schulung, Support?

## Typische Fallen in Phase 2

1. **Der Pilot wird heimlich zum Projekt.** Scope wächst, Termin rutscht. Gegenmittel: Charter gilt, Erweiterungen sind Phase-3-Material.
2. **Die Metrik wird nachträglich umdefiniert,** weil das Ergebnis enttäuscht. Gegenmittel: Baseline und Zielmetrik sind ab Tag 37 eingefroren.
3. **Begeisterte Einzelnutzer, aber kein Prozesseffekt.** Ein Tool, das 2 von 12 Leuten lieben, hat den Prozess nicht verändert. Messen auf Team-, nicht auf Personenebene.
