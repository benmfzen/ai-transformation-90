# Team Lead Coaching — From "We Want More AI" to a Shipped Outcome

The transformation part of this role is not workshops — it is making ten team leads measurably more effective, one negotiated goal at a time. This file shows the working method.

## The AI Goal Canvas (one page per team, per cycle)

| Field | Filled example (Performance Marketing) |
|---|---|
| **Business goal this serves** | Marketing efficiency: more validated creative tests per euro |
| **Type** | Opportunity |
| **Outcome statement** | By end of Q3, creative testing throughput doubles (8 → 16 validated tests/month) at flat production cost |
| **Baseline** | 8 tests/month; €1,400 avg. production cost per variant set |
| **Metric & measurement** | Tests entering the ad account/month; cost per variant set; win-rate tracked but not targeted |
| **What AI does / what humans do** | AI drafts variant copy+visual briefs from a winning ad; team selects, refines, launches |
| **First evidence by** | Day 14: 4 AI-assisted variant sets live |
| **Owner / staffing** | Aylin Kaya; 1 creative + 1 media manager at 20% |
| **Not doing** | No auto-publishing; no budget reallocation by AI |

## The conversation that produces it

> **Lead:** "We want to use AI 30% more in marketing."
> **Coach:** "What would be different in the business if that worked?"
> **Lead:** "We'd… test more creatives, probably."
> **Coach:** "How many do you test now, and what does one cost?"
> **Lead:** "Eight a month, maybe €1,400 each."
> **Coach:** "So the goal isn't 'more AI' — it's sixteen tests a month at today's budget. If AI doesn't get you there, we don't care about AI. What's the first evidence we could see in two weeks?"

The pattern: **usage goals become outcome goals, outcome goals get baselines, baselines get a first-evidence date.** "30% more AI" is not a goal; it's a symptom of not having one.

## Stop / iterate / scale — the decision tree at pilot end

```
Did the metric move ≥ target?
├── YES → Did quality hold (rubric ≥ baseline)?
│         ├── YES → Is adoption organic (>70% of team uses it unprompted)?
│         │         ├── YES → SCALE (rollout plan + budget to C-level)
│         │         └── NO  → ITERATE on workflow, not model (2 weeks, once)
│         └── NO  → ITERATE on quality gates (2 weeks, once)
└── NO  → Is there one identified, fixable cause?
          ├── YES → ITERATE (2 weeks, once — then this branch exits to STOP)
          └── NO  → STOP, document, return the slot to the portfolio
```

One iteration, maximum. The second "just two more weeks" is how zombie pilots are born.

## The difficult conversation (worked example)

**Situation:** Supply Chain lead (Tomasz) is frustrated — his forecasting initiative scored highest on value and still didn't get a pilot slot ([portfolio #11](portfolio.md)).

**The move:** don't defend the scoring — show it, then convert the frustration into the data project. *"You have the biggest prize in the portfolio and the worst data to win it with. If we pilot now, you get a six-month science project and I get to explain to the board why the highest-value initiative failed. Or: we spend Q1 getting your three data feeds in shape, and you walk into Q3 with the strongest pilot of the year. Which story do you want to be in?"* — Tomasz co-owns the data project charter by end of week. Readiness scores exist to time initiatives, not to rank people; saying that out loud is the job.

## Team lead scorecard (reviewed quarterly, coached not policed)

| Dimension | Signal |
|---|---|
| Outcome progress | Metric vs. canvas target |
| Adoption | % of team actively using the shipped capability |
| Fluency | Lead can explain what the system does and where it fails |
| Contribution | Recipes/feedback flowing back into the champions circle |

The scorecard's purpose is to make coaching concrete — it feeds the next canvas conversation, never a ranking of leads.
